# HHton: платформа для хакатонов

Этот репозиторий содержит набор Rust-крейтов, из которых собирается gRPC‑сервис для управления хакатонами, командами и их репозиториями. Ниже приведены сведения о назначении каждого крейта, текущем состоянии реализации и ближайших задачах.

## Архитектура и реализованные возможности
- **Контракты (`crates/contracts`)** — protobuf/gRPC контракты для всех сервисов (участники, события, отправка решений, рейтинги, проверка репозиториев). Код генерируется `tonic-build` и используется как клиентами, так и серверными обработчиками.
- **Домен (`crates/core-domain`)** — модель предметной области: агрегаты хакатона, команды, пользователи и рейтинги, а также сервисы, проверяющие инварианты (сроки регистрации/подачи решений, лимиты размера команды и т. д.).
- **Хранилище данных (`crates/persistence`)** — тонкая обёртка над пулом подключений `sqlx` и место для миграций и репозиториев.
- **Хранение артефактов (`crates/storage`)** — работа с S3‑совместимым объектным хранилищем: загрузка архивов решений, сохранение/чтение метаданных и артефактов.
- **Проверка репозиториев (`crates/repo-proof`)** — клиент и сервер для gRPC‑сервиса проверки привязки репозитория (провайдер, репозиторий, коммит); есть простая встроенная реализация валидации формата данных.
- **Рейтинги (`crates/ratings`)** — вычисление рейтингов на основе результатов событий: нормализация баллов, веса в зависимости от масштаба мероприятия, штраф за размер команды, затухание по времени.
- **Поиск (`crates/search`)** — базовый парсер поисковых запросов с токенизацией и валидацией.
- **Хуки (`crates/hooks`)** — заглушки для регистрации и публикации событий жизненного цикла.
- **Сервер (`crates/hackcore-server`)** — gRPC‑сервер, объединяющий обработчики участников, событий, отправок решений и рейтингов, а также интеграции с хранилищем артефактов и сервисом repo-proof. Предусмотрен запуск на Unix‑сокете и подключение к PostgreSQL/S3.

## Что уже сделано
- Описаны доменные модели и инварианты для ключевых сущностей (хакатон, команда, отправка решения, рейтинг).
- Реализованы gRPC контракты и каркасы серверных обработчиков с интеграцией хранилища, S3 и проверок репозиториев.
- Добавлены клиенты/серверы для проверки репозитория и базовая логика расчёта рейтингов.
- Поддержана работа с объектным хранилищем для архивов отправок и метаданных.

### Реализованные фичи по сервисам
- **Участники/команды**: контракты `ParticipantsService` позволяют получать участника и постранично перечислять участников; в домене описаны правила формирования команды (лимиты размера, уникальность участия) и проверки возможности вступления/выхода.
- **Хакатоны/мероприятия**: `EventsService` предоставляет получение и список событий с дедлайнами регистрации и подачи, доменные сервисы проверяют окна регистрации/отправки и корректность ограничений по времени.
- **Отправки решений**: `SubmitsService` принимает решение от команды с привязкой репозитория и сохраняет историю проверок; слой `storage` умеет загрузить/выдать архив решения и связанные метаданные, а `repo-proof` выполняет проверку привязки репозитория.
- **Рейтинги**: крейт `ratings` поддерживает пересчёт профиля участника на основе результатов событий, нормализуя баллы, учитывая масштаб мероприятия и штрафы за размер команды.
- **Поиск и хуки**: базовый парсер поисковых запросов (`search`) для будущего индекса и заглушки хуков (`hooks`) для публикации событий жизненного цикла, которые можно расширить под очереди и вебхуки.

- Добавить полноценный индекс и движок для поиска по хакатонам/командам/репозиториям.
- Покрыть код тестами интеграции, настроить CI и документацию по деплою (Docker/Kubernetes).

## Запуск и конфигурация
- Переменная окружения `S3_BUCKET` указывает имя S3‑бакета для сохранения артефактов (в docker-compose создаётся MinIO бакет по умолчанию).
- `REPO_PROOF_ENDPOINT` задаёт gRPC‑адрес сервиса проверки привязки репозитория (по умолчанию `http://127.0.0.1:50060` в docker-compose).
- Для локального запуска через Docker Compose используйте `make up`; для разработки вне Compose настройте PostgreSQL, MinIO/S3 и запустите бинарь `hackcore-server`.

## Swagger UI для C++ сервиса конфигурации хакатонов
- Поднимите сервисы хакатон-конфига и Postgres командой `docker compose up -d postgres` и сборкой самого сервиса (см. `cpp/services/hackathon-config`).
- Для просмотра документации OpenAPI поднимите `swagger-ui`: `docker compose up -d swagger-ui`.
- Swagger UI будет доступен по адресу http://localhost:8081 и автоматически загрузит спецификацию из `cpp/services/hackathon-config/openapi.yaml`.
